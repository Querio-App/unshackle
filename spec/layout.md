# The unshackle layout

This is the layout `unshackle` writes into a target repo. The files can be read and
edited directly. Everything here matches what `src/unshackle/target/*` and
`src/unshackle/scaffold.py` emit. A folder exists only once something is written to it.

```
AGENTS.md                         read-me for agents (created once by `unshackle init`)
unshackle.toml                       workspace config + [paths]
semantic/*.ossie.yaml             Apache Ossie semantic models, one document per model
catalog/<datasource>/<schema>/<table>.yml
knowledge/*.md                    markdown with frontmatter
queries/*.sql | *.py              verified queries with a comment header
queries/models/*.sql              SQL models for pre-aggregated logic (paths.sql_models)
notebooks/<name>.ipynb            dashboards as Jupyter notebooks (SQL + Altair)
policies/schema.cedarschema       Cedar schema
policies/<tool>.cedar             Cedar policies
policies/row_filters.<tool>.yml   row-level rules as SQL predicates
evals/*.yaml                      question -> expected answer (written by `unshackle verify`)
data/<tool>/                      data copied out of the tool (`--with-data`), git-ignored
migration/                        unshackle's working area (see below)
```

## unshackle.toml and [paths]

`unshackle init` writes it once and never updates it. No secrets: credentials come from
the environment or `.unshackle/` (git-ignored).

```toml
[workspace]
name = "acme-analytics"

[paths]
semantic = "semantic"
catalog = "catalog"
knowledge = "knowledge"
queries = "queries"
notebooks = "notebooks"
policies = "policies"
evals = "evals"
sql_models = "queries/models"
data = "data"

[datasources.warehouse]
# type = "postgres"   # snowflake | bigquery | databricks | redshift | postgres | duckdb
```

Every writer resolves folders through `[paths]`, so the structure can live inside an
existing repo. **dbt co-location:** when `dbt_project.yml` exists at the repo root,
defaults become `semantic = "models/semantic"` and `sql_models = "models/unshackle"`,
MetricFlow YAML is written next to the Ossie documents (models reference dbt models
with `model: ref('<name>')`), and `*.ossie.yaml` is added to `.dbtignore` so dbt
doesn't read Ossie files as properties. Any key set in `unshackle.toml` wins over the
defaults. `[datasources.<name>] type` picks the dialect Ossie expressions are labelled with.
`init` leaves it unset. At build the type comes from `unshackle.toml` if set, else from
what the export reports (Lightdash warehouse connection or explore `targetDatabase`,
Tableau connection class, Power BI M connector), else expressions are labelled `ANSI_SQL`
and the report warns until you set it.

**Default time dimension:** the one the source declares (Lightdash, Omni), else the
model's only time dimension. With several and none declared nothing is picked:
MetricFlow measures stay commented out with a `TODO(unshackle)` listing the candidates
for `defaults.agg_time_dimension`, and the Ossie file gets the same TODO.

## semantic/ (Apache Ossie)

One [Apache Ossie](https://github.com/apache/ossie) document per semantic model,
named `<model>.ossie.yaml`, valid against the spec's JSON Schema (`core-spec/ossie-schema.json`,
version `0.2.0.dev0`). The model's own table is the first dataset. Ossie has no
references between documents, so the datasets it joins to through foreign entities
are copied in (without their metrics, `defined_in` names their own file); that's
what lets relationships and cross-dataset metrics resolve.

```yaml
# Generated by unshackle from looker. Edit freely: re-runs keep hand edits.
version: 0.2.0.dev0
name: orders
datasets:
- name: orders
  source: analytics.fct_orders
  primary_key: [order_id]
  fields:
  - name: status
    expression:
      dialects:
      - {dialect: SNOWFLAKE, expression: status}    # [datasources.*] type; else ANSI_SQL
    dimension: {is_time: false}
  - name: created
    expression:
      dialects:
      - {dialect: SNOWFLAKE, expression: created_at}
    dimension: {is_time: true}
  metrics:                                           # read only this dataset's fields
  - name: average_order_value
    expression:
      dialects:
      - {dialect: SNOWFLAKE, expression: '1.0 * SUM(amount) / nullif(COUNT(order_id), 0)'}
    custom_extensions:
    - vendor_name: UNSHACKLE
      data: '{"label": "Average Order Value", "source_ref": "orders.view.lkml ..."}'
- name: customers                                    # copy: edit customers.ossie.yaml
  source: analytics.dim_customers
  primary_key: [customer_id]
  fields: [...]
  custom_extensions:
  - {vendor_name: UNSHACKLE, data: '{"defined_in": "customers.ossie.yaml"}'}
relationships:
- {name: orders_to_customers, from: orders, to: customers, from_columns: [customer_id], to_columns: [customer_id]}
metrics:                                             # read several datasets: dataset.field
- name: large_orders_outside_eu
  expression:
    dialects:
    - {dialect: SNOWFLAKE, expression: "COUNT(CASE WHEN orders.is_large_order = true AND customers.region <> 'EU' THEN orders.order_id END)"}
```

| unshackle model | Ossie |
| --- | --- |
| semantic model | document + its first dataset (`source` = table) |
| dimension | field; time dimensions have `dimension.is_time: true`, granularity in `custom_extensions` |
| entity | key field; `primary` -> `primary_key`, `unique` -> `unique_keys` |
| foreign entity | relationship to the dataset whose primary entity has that name |
| measure | field holding its row-level expression (`<name>_value` when a metric has the name) |
| simple metric | `AGG(field)`; a filter becomes `CASE WHEN <filter> THEN field END` inside it |
| ratio metric | `1.0 * num / nullif(den, 0)`, both sides inlined |
| derived metric | its `expr` with each input metric's expression inlined |
| label, source reference, default time dimension | `custom_extensions`, vendor `UNSHACKLE` (JSON) |

Not written as fields or metrics: anything with a `todo`, cumulative metrics,
`offset_window`, conversion metrics, and anything depending on them. They're kept
whole under `custom_extensions` (`UNSHACKLE`, key `pending`; on the dataset for
dimensions and measures, on the model for metrics) with a
`# TODO(unshackle): <kind> <name>: <why>` line at the end of the file. Ossie-specific
gaps are also listed as warnings in `migration/report.md`.

### MetricFlow (dbt projects only)

When `dbt_project.yml` exists, `models/semantic/<model>.yml` holds the same model as
MetricFlow, and metrics whose model could not be resolved go to
`_<tool>_metrics.yml`. The output passes `dbt parse`.

```yaml
# Generated by unshackle from looker. Edit freely: re-runs keep hand edits.
semantic_models:
- name: orders
  description: Orders
  model: ref('fct_orders')
  defaults:
    agg_time_dimension: order_date
  entities:
  - name: order
    type: primary
    expr: id
  dimensions:
  - name: order_date
    type: time
    type_params:
      time_granularity: day
  - name: region
    type: categorical
  measures:
  - name: revenue
    agg: sum
    expr: amount
    label: Revenue
metrics:
- name: revenue
  label: Revenue            # the original BI name
  type: simple
  type_params:
    measure: revenue
```

Untranslated items are commented out under a
`# TODO(unshackle): <kind> <name>: <why> [<language>] <original>` line.

## catalog/

One file per table at `catalog/<datasource>/<schema>/<table>.yml`.

```yaml
name: fct_orders
description: One row per order
source: tableau://datasource/abc
columns:
- name: id
  type: integer
  description: Order id
- name: amount
  type: number
  label: Order amount       # only when it differs from name
  visible: false            # hidden in the BI tool
```

## knowledge/

Markdown with YAML frontmatter. `context: always` applies to every answer;
`reference` is looked up when relevant. File name is the slug of `name`.

```markdown
---
name: Glossary
description: Business terms used across finance dashboards
context: always
datasource: warehouse
source: looker
---

**Net revenue** excludes refunds and tax.
```

## queries/

Verified queries. SQL uses `--` headers, Python uses `#`. `metric: true` marks a query
that is the definition of a number (use it when Ossie or MetricFlow can't express it).

```sql
-- name: Top customers
-- description: Top 10 customers by net revenue, last full quarter
-- datasource: warehouse
-- metric: true
-- aliases: best customers, biggest accounts
-- owner: finance@acme.com
-- source: hex://project/123/cell/456
select customer_id, sum(net_revenue) as revenue
from analytics.fct_orders
group by 1 order by 2 desc limit 10
```

Header keys: `name`, `description`, `datasource`, `metric`, `aliases` (comma list),
`owner`, `source`. Empty keys are omitted. File name is the slug of `name`.

## notebooks/

One Jupyter notebook per dashboard at `notebooks/<slug>.ipynb` (nbformat 4.5, saved
without outputs so diffs stay readable). It runs in Jupyter, VS Code, Colab or anything
that opens `.ipynb`, and renders on GitHub. Cells, top to bottom:

| Cell | Id | Contents |
| --- | --- | --- |
| markdown | `title` | `# <dashboard name>`, description, source, link to the original |
| code | `setup` | imports; `engine = create_engine(os.environ["UNSHACKLE_WAREHOUSE_URL"])` (with data copied by `--with-data`: that URL if set, else the DuckDB file `build` loaded, read-only) |
| code | `parameters` | tagged `parameters` (papermill): one `name = default` per dashboard filter |
| per tile, in layout order: | | |
| markdown | `<tile>-title` | `## <tile title>` |
| code | `<tile>-sql` | `<tile>_sql = """..."""` and `<tile> = pd.read_sql(text(<tile>_sql), engine, params={...})` |
| code | `<tile>-chart` | `<tile>_chart = alt.Chart(<tile>)...` (table tiles show the DataFrame instead) |
| markdown | `<tile>` | text tiles |

```python
# parameters
date_from = '2025-01-01'
```

```python
monthly_revenue_sql = """
select month, region, revenue from rev where month >= :date_from
"""
monthly_revenue = pd.read_sql(text(monthly_revenue_sql), engine, params={'date_from': date_from})
```

```python
monthly_revenue_chart = (
    alt.Chart(monthly_revenue)
    .mark_line(point=True)
    .encode(
        x=alt.X('month:T'),
        y=alt.Y('revenue:Q'),
        color=alt.Color('region:N'),
    )
    .properties(title='Monthly revenue')
)
monthly_revenue_chart
```

Rules: filters are `:name` binds (`::type` casts are safe) whose values come from the
parameters cell, so `papermill -p date_from 2025-06-01` works. Charts are Altair, which
compiles to Vega-Lite. Use whatever the source chart needs: facets (`row`, `column`,
`facet` channels or `.facet()`), layers (`alt.layer`, dual axis with
`.resolve_scale(y='independent')`) and concatenation (`alt.hconcat`, `alt.vconcat`).
A tile with several series is written as a `base` chart with the shared encodings and one
layer or panel per series. Notebook metadata `unshackle.layout` keeps the source layout
rows (tile names left to right) for tools that want to rebuild the grid.
`unshackle run notebooks/x.ipynb` with `UNSHACKLE_WAREHOUSE_URL` set executes
it and writes `notebooks/x.html` (git-ignored); the notebook itself is not changed. Without
arguments it runs every notebook and reports, per dashboard, tiles, tiles with SQL, tiles
that ran, tiles that returned rows, and errors.

## policies/

`schema.cedarschema` (as generated):

```
entity Group;
entity User in [Group] { email: String, };
entity Datasource;
entity Table in [Datasource];
entity Column in [Table];
entity Metric in [Datasource];
entity Notebook;
action "view"  appliesTo { principal: [User], resource: [Notebook, Metric, Datasource, Table, Column] };
action "query" appliesTo { principal: [User], resource: [Datasource, Table, Column, Metric] };
action "edit"  appliesTo { principal: [User], resource: [Notebook, Metric] };
```

`<tool>.cedar`:

```
// Generated by unshackle from tableau. Review before enforcing.

// source: tableau://project/Finance capability Read
permit (
  principal in Group::"finance",
  action == Action::"view",
  resource in Notebook::"revenue-overview"
);
```

Entity ids: `Notebook` = notebook file stem, `Metric` = metric name, `Datasource` =
datasource name, `Table` = `<datasource>.<schema>.<table>`, `Column` =
`<datasource>.<schema>.<table>.<column>`. Groups come from the identity provider.

`row_filters.<tool>.yml`:

```yaml
row_filters:
- name: region_scope
  table: analytics.fct_orders
  predicate: region = {{ user.region }}
  groups:
  - sales                   # who it applies to; ["*"] = everyone
  source: tableau://datasource/abc user filter
```

`{{ user.<attr> }}` is replaced with the querying user's attribute from the IdP.

## evals/

- `evals/<slug>.yaml`: written by `unshackle verify` for each passing parity case:

```yaml
name: Monthly revenue by region
question: What was revenue by region per month?
target:
  notebook: notebooks/revenue-overview.ipynb
  tile: monthly_revenue
keys: [month, region]
tolerance: 0.0001
expected:
  rows: 2
  sample:
  - {month: '2025-02-01', region: EU, revenue: 10.0}
source: unshackle parity check
```

## migration/

Written by unshackle only.

| Path | What |
| --- | --- |
| `raw/<tool>/` | untouched exports + `_manifest.json` (sha256 per file); after `unshackle import`, also `_import.json` (`origin: manual`, the inputs, and what the files can't carry, which the report lists) |
| `ir/<tool>.json` | the parsed neutral bundle |
| `inventory.<tool>.md` / `.json` | everything in the tool, with views where available |
| `report.md` | counts, files kept as hand edits, remaining TODOs, warnings, parity |
| `parity/*.yaml` | parity cases (hand-written); `parity/results.json` (generated) |
| `unshackle.lock` | hash of every generated file and every raw file |

## Naming

- Metrics, measures, dimensions, entities, semantic models: `snake_case` of the BI
  name; the original name is kept as `label`.
- Notebooks, queries, knowledge, evals: slug of the name (`revenue-overview.py`).
- Notebook tile idents: `snake_case` of the tile title; `tile_` prefix when it would
  start with a digit or clash with a Python keyword/builtin.

## Generated vs hand-written, and re-runs

| File | Who writes it | On re-run |
| --- | --- | --- |
| `AGENTS.md`, `unshackle.toml` | `unshackle init`, only if missing | never touched |
| `.gitignore` | `unshackle init` creates it, or appends `.unshackle/`, `*.html`, `.env` | never touched again |
| semantic, queries, knowledge, notebooks, policies | `unshackle build` | rewritten only if unchanged since last build (lock hash matches) |
| catalog | `unshackle build` | always rewritten, merging what's in the file: column `description` and `visible: false`, table `description`, and `label` (only where the source also has a label) are kept, as are columns the source no longer has; other hand-added keys are dropped |
| `evals/*.yaml` | `unshackle verify` | overwritten for every passing case |
| parity cases | people / agents | never touched |

A file that differs from its lock hash, or that existed before unshackle and isn't in
the lock, is kept and listed under "kept because someone edited them by hand" in
`migration/report.md`. Anything still containing `TODO(unshackle)` is listed by
`unshackle todo` and should not be trusted until resolved.
