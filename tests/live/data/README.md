# Live test data

`dunder_mifflin/*.csv` is **synthetic**. Nothing in it is real: company names,
account managers (characters from The Office), orders and reviews are generated by
`generate.py` (stdlib only, seeded, so every run writes the same files):

```
python tests/live/data/generate.py
```

It follows the schema and distributions of the Dunder Mifflin demo database (a fictional
B2B paper company): `accounts`, `products`, `orders` (one per purchase, H1 2025, ~2.7 a day
with seasonal multipliers, status 84% COMPLETED / 10% CANCELLED / 6% RETURNED),
`shippings` (one per order) and `reviews` (~67% of completed orders, 7-30 days later).
About 490 orders in total.

The harness (`harness.Stack.load_csvs`) loads **every** `*.csv` in a dataset folder into
Postgres as `public.<file name>`, inferring column types (bigint, numeric, timestamp,
date, boolean, text; empty = NULL). To use another snapshot, replace the CSVs: no code
change is needed for loading. If its column names differ, update the dbt project
(`tests/live/lightdash/dbt/models/schema.yml`) and the content that references them.
